# Откуда данные и как всё посчитано

Состояние на 2 октября 2026. Документ описывает, откуда взят каждый набор данных, как он загружен и обработан и чем проверен результат. Подробности с цифрами лежат в отчётах `s2_facility_inventory.md`, `s2b_population.md`, `s3_walk_access.md`, `data_strategy.md`.

## 1. Главные правила

1. Только реальные открытые данные, которые любой может открыть сегодня. Синтетических данных нет. Каждое производное значение получено из наблюдаемых по записанному правилу и помечено как оценка.
2. Ничего не ждёт официальных ответов. Если ответ придёт, он заменит оценку, но работа от него не зависит.
3. Ограничения сайтов соблюдаются. Если `robots.txt` запрещает автоматический доступ, сайт не скачивается кодом. Капчи не обходятся, аккаунты не создаются.
4. Каждый производный слой проверяется по источнику, который не использовался при его построении.

## 3. Как посчитано, по шагам

Весь расчёт запускается одной командой и проходит 11 этапов: `boundary`, `worldpop`, `grid`, `osm`, `schools`, `preschools`, `population`, `access`, `models`, `programme`, `figures`.

### 3.1. Школы

1. Реестр egov устарел: в нём 4 района вместо 6 и нет новых школ с номерами выше 85. Поэтому список школ строится как объединение реестра и OSM.
2. Записи реестра связаны с объектами OSM по номеру, типу, названию и району: оценка близости пар и оптимальное сопоставление венгерским алгоритмом. Качество проверено на вручную размеченном эталоне из 112 записей: F1 0.98.
3. Отобраны государственные школы с приёмом по микроучастку: 111 школ. Частные и конкурсные школы (НИШ, лицеи, интернаты) исключены, потому что не обслуживают свой район.
4. Мощность школы: проектная вместимость известна только для 11 школ, поэтому используется площадь здания из OSM (есть у 96 школ) и пересчёт в места по одному городскому коэффициенту 13.5-17.3 кв. м на место.

### 3.2. Детсады

1. Реестр взят с портала очереди: название, адрес, форма собственности, язык, возраст групп, свободные места.
2. Адреса переведены в координаты собственным геокодером по адресам OSM. Он учитывает русские, казахские, старые и альтернативные названия улиц, переулки, инициалы, фонетические варианты. Принимается только точное совпадение дома.
3. Результат: 653 детсада стоят точно у своего здания, 75 приблизительно, 62 не найдены. Проверка по зданиям 70 государственных детсадов в OSM: медианная ошибка 9 м.

### 3.3. Население ниже уровня района

Официальных данных о населении внутри районов нет, поэтому построена своя модель.

1. Классификатор жилых зданий. Модель LightGBM учится на зданиях с известным типом и на домах из списков избирательных участков и микроучастков, затем определяет остальные 79 677 зданий. Проверка: пространственная кросс-валидация блоками 1 км, ROC-AUC 0.98; на домах, которых модель не видела, находит 80 процентов жилых.
2. Этажность. Где не указана, берётся медиана семи ближайших домов в пределах 400 м. Ошибка при проверке с исключением: 2 этажа.
3. Территории участков. Текст решения акима разобран программой: 93 участка заданы списком домов, 290 описанием границы по улицам. Многоугольники восстановлены по пересечениям улиц для 247 участков; 246 из них попали в тот район, который указан в решении.
4. Распределение. Официальная численность района делится между участками примерно поровну (доля пропорциональна жилой площади в степени 0.2). Внутри участка люди распределяются по жилой площади домов, частный дом весит в 2.15 раза больше квартиры на квадратный метр. Коэффициент 2.15 выведен из сравнения с официальным жилым фондом.
5. Число детей по возрастам берётся из долей WorldPop в каждой ячейке.

Проверка (гипотеза H1): число участков в районе предсказывает население района с ошибкой 8.7 процента, WorldPop с ошибкой 27.6, жилая площадь с ошибкой 27.8. Сохранены четыре варианта населения, и все дальнейшие результаты пересчитаны на каждом.

Население на 2023 год построено так же: здания, существовавшие в OSM на 1 января 2023 года, и официальные итоги районов на ту же дату.

### 3.4. Пешеходная сеть и нормативы

1. Граф из всех пешеходно доступных дорог OSM: 152 491 узел, 5 934 км. Расстояния считаются алгоритмом Дейкстры до 4 км.
2. Проверка: путь по сети ни разу не короче прямой, медианное отношение 1.41.
3. Нормы СП РК: детсад в радиусе 300 м, школа в радиусе 500 м. Посчитаны два прочтения нормы: по прямой и пешком.
4. Проверка предпосылки «идут в ближайшую школу» по официальным микроучасткам 11 школ: ближайшая назначена только в 57 процентах домов, медианный путь до своей школы 1 133 м.

### 3.5. Индекс доступности и неравенство

1. Индекс E2SFCA: для каждой школы или детсада считается отношение мощности к числу детей вокруг, затем для каждого места жительства складываются отношения всех учреждений в пешей доступности с весом, убывающим с расстоянием.
2. Своё улучшение: каждый ребёнок распределяется между учреждениями один раз (3 км для школ, 2 км для детсадов), а не засчитывается каждой школе в радиусе. Вариант выбран по реальному контингенту 10 школ.
3. Неравенство: коэффициент Джини, индекс Тейла с разложением на межрайонную и внутрирайонную части, глобальный индекс Морана и локальные кластеры LISA (999 перестановок).
4. Устойчивость (гипотеза H3): 48 вариантов на каждый тип учреждения: 4 модели населения, 2 меры мощности, 3 функции затухания, 2 радиуса.

### 3.6. Машинное обучение

1. Классификатор жилых зданий (раздел 3.3).
2. Модель свободных мест в детсадах: связь опубликованных свободных мест с числом детей вокруг. Логистическая регрессия и LightGBM, пространственная кросс-валидация блоками 2 км.
3. Объяснение моделей через SHAP, рисунки в `thesis/figures/`.

### 3.7. Проверка «Комфортной школы» (гипотеза H4)

1. Город восстановлен на 1 января 2023 года, до программы: здания, население, свободная земля.
2. Свободная земля: растр 10 м, на котором исключены здания, дороги, вода, парки, промзоны, стройки и т. п. Участок годится, если на нём помещается 3.8 га, как требует СП РК для школы на 2 000 мест. Найден 191 участок.
3. Тест выбора мест: насколько хорошо выбранные места отделяются от остальных по дефициту доступности и по плотности населения (ROC-AUC с бутстрепом).
4. Оптимизация: задача максимального покрытия с ограничением вместимости, 21 школа, точное решение через scipy (HiGHS). Сравниваются три варианта: без ограничения по земле, только на свободных участках 2023 года, и реальная программа. Дополнительно программа сравнивается со случайным выбором мест.

## 5. Что не использовано и почему

| Источник | Почему нет |
|---|---|
| Автоматический обход портала детсадов | Запрещён в robots.txt; страницы сохраняются вручную |
| Школы портала Sakura вне публичного списка | Не опубликованы, дата неизвестна; используются только 11 опубликованных |
| Места из Overture Places | Только 75 детсадов против 790 в реестре |
| Сайты gov.kz | Недоступны из рабочей сети; цифры взяты из СМИ, перепечатывающих релизы |
| Поиск через DuckDuckGo | Показывает капчу; капча не обходится |
| 2GIS | Нужен ключ API; по желанию автора |

## 6. Ограничения

1. Население внутри районов является оценкой: проверить его можно только косвенно.
2. 46 территориальных участков без восстановленной границы, их жители отнесены к соседним участкам того же района.
3. Проектная вместимость известна для 11 школ из 111, поэтому мощность оценена по площади здания.
4. Свободные места детсадов взяты за один вечер (30.09.2026).
5. 137 детсадов не найдены или стоят приблизительно.
6. Две школы программы не найдены на карте.
7. Собственник свободной земли в 2023 году неизвестен.
8. Нормы взяты из редакции СП РК 2021 года; редакцию 2025 года нужно сверить.

## 7. Как воспроизвести

```bash
uv sync
uv run python -m astana_access.pipeline run
uv run python -m astana_access.pipeline run --start access --stop figures
uv run pytest
```

Первая команда ставит зависимости. Вторая проходит все этапы, третья только часть. Четвёртая запускает 70 тестов. Ключ egov читается из `.env` и нигде не печатается. Страницы портала детсадов нужно положить в `data/raw/manual/` вручную.
